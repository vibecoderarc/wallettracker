# Deploying to Render

## The whole thing

1. Go to **Render → New → Blueprint** and pick this repository.
2. Click **Apply**.
3. Wait, then open the `alphagraph-web` URL.

That's it. There is nothing to type, no shell to open, and no configuration to
fill in.

The dashboard is reachable a minute or two after the deploy finishes, but it
starts **empty** and fills itself in over the next few minutes — it seeds
automatically on first boot. If you open it early you'll see "No signals yet".
That is not an error. Refresh in a few minutes.

---

## What gets created

| Service | What it is |
| --- | --- |
| `alphagraph-web` | The dashboard — this is the URL you open |
| `alphagraph-api` | The engine behind it |
| `alphagraph-nightly` | A daily job that grades yesterday's alerts |
| `alphagraph-db` | The database |

Roughly $25-30/month for all four. Avoid the Free tier: free services fall
asleep, and a sleeping engine makes the dashboard show errors until it wakes.

---

## Things you do NOT need to do

- **You do not need to seed the database.** It seeds itself on first boot.
- **You do not need to configure CORS.** The dashboard talks to the engine
  server-to-server, so no browser origin is involved.
- **You do not need to handle any password.** Render generates the API token and
  gives it to all three services automatically.

---

## If something looks wrong

**"Cannot reach the AlphaGraph API"** — the engine is still starting, or failed.
Open `alphagraph-api` in Render and read its Logs tab.

**Still empty after 15 minutes** — the seed may have failed. Search the
`alphagraph-api` logs for `auto-seed`; it logs when it starts, finishes, or
fails. A failed seed leaves the API running, so the site stays up either way.

**You want to start over** — empty the database and restart the API service. It
seeds any empty database. Or open a Render Shell on `alphagraph-api` and run
`alphagraph demo`, which does the same plus a backtest.

## Wiring, for reference

All of this is already set up in `render.yaml`. You do not need to touch it; it
is written down so nothing is a mystery.

- `ALPHAGRAPH_API_TOKEN` — generated by Render, shared with all three services.
  Every endpoint except the health check requires it, and the engine refuses to
  start without one outside local development, so it cannot end up open to the
  internet by accident. To call the API yourself, copy the value from the
  `alphagraph-api` service's Environment tab.
- `ALPHAGRAPH_RUN_MODE=shadow` — everything computes, nothing is sent. Change to
  `live_alerts` (and add a destination) only after reviewing shadow output.
- `ALPHAGRAPH_PROVIDER_MODE=fixture` — running on the synthetic world. Auto-seed
  only ever writes in fixture mode, so it cannot contaminate real data.
- `ALPHAGRAPH_AUTO_SEED` — set to `false` to disable the first-boot seed.
- The nightly job runs at **07:00 UTC**, not your local morning.
- All services are pinned to one region, so the engine is not reaching across
  regions for its database.

## Later: real data

1. Implement the interfaces in `packages/alphagraph/providers/base.py`.
2. Set `ALPHAGRAPH_SOLANA_RPC_URL` and the other provider variables.
3. Set `ALPHAGRAPH_PROVIDER_MODE=live`. The service refuses to boot in live mode
   without a chain provider rather than reporting empty coverage, and auto-seed
   switches itself off.
4. Leave `ALPHAGRAPH_RUN_MODE=shadow` until you have reviewed several weeks of
   output.

## Later: schema changes

Tables are created with SQLAlchemy's `create_all()` on startup, which handles
new tables and new columns. It does **not** handle changing or dropping an
existing column. Alembic is already a dependency but no migrations are written
yet; one is needed before the first altering change, or that deploy will fail
confusingly or run against a stale schema.

## Testing against Postgres

Development uses SQLite, production uses Postgres, and the differences are real —
one defect was found only by running against Postgres. Before changing anything
that touches the database:

```bash
createdb alphagraph_pytest
ALPHAGRAPH_TEST_DATABASE_URL=postgresql+psycopg://user:pass@localhost/alphagraph_pytest \
  pytest -q
```
